Simulated ledger

Solana accounts

Each card is an account: an address, lamports, an owner, an executable flag, and data. Send a transaction and the cards move. Then turn a check off and run an attack.

Local simulation. No RPC, no wallet, no cluster. System, loader, and SPL Token ids are the real ones. Every other address is a stand-in.

Till’s checks

The runtime stays on. It still rejects a missing signature, a program that is not executable, and a debit by anyone but the owner. The switches are the checks a program has to remember.

Transaction

Helius describes Solana as a global key/value store. The public key is the key. The account is a memory region that holds programs and balances, and a transaction updates it. is_signer and is_writable come from that transaction, not from the account. One lamport is one-billionth of a SOL. A transaction here is atomic: if an instruction fails, only the 5,000 lamport fee remains.

The attacks are the five in Neodyme’s common pitfalls: missing owner check, missing signer check, integer wrap, an unchecked program id on invoke, and account confusion. The exemption floor is a stand-in for two years at 3,480 lamports per byte-year. This page does not collect rent and does not contact a cluster.
