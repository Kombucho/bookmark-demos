Who can replace the binary

Upgrade authority

Four fictional vaults. The upgrade authority can swap in a program that drains the deposits. Switch the mode, collect signatures, and try.

Local simulation. No RPC, no wallet, no real program ids. Every name on this board is made up.

Day 0

On Solana the upgrade authority can replace the program binary. A single key signs, and the new code is what runs on the next transaction. A multisig needs enough members. A governance council needs enough weight. Setting the authority to None makes the program immutable. A timelock only delays a signature that already passed. Turning a key off later does not pull the queued binary back. Cancel does.

The drain instruction is fictional. It stands in for replacing a vault with a program that withdraws every deposit to the upgrader. The instructions that were already there did not have to be buggy. Auditing the current binary does not answer who can replace it.

From Neodyme’s discussion of upgrade authorities and the bookmarked thread. Hot key, cold key, multisig, DAO, and locked are the options they weigh. Nothing here contacts a cluster.
