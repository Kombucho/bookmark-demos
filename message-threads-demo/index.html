Bytes are the compact JSON body. Tokens are that string’s length divided by 4. Time to first token is 140 ms plus 0.42 ms for each body byte, standing in for upload and a fresh tokenize of what this request sends. Headers are shown and not counted. Prompt caching is a separate feature. A thread does not cache the prompt for you. The cache_control field is included because the docs send it on every turn of a thread. These figures are simulated.

From the Claude Developers post: message threads are in public beta on the Messages API, the API keeps the conversation between turns, and a later request sends only the new messages and the previous message id. The bodies here follow Message threads. The beta header is message-threads-2026-08-12. Turn 1 uses "thread": {"type": "create"} with system and tools. Later turns use "thread": {"type": "continue", "previous_message_id"} and leave system and tools out. model stays. A thread is best-effort: the docs say it expires 5 minutes after its last request, and a continue that can no longer be served returns 404, so the app keeps its own copy and replays with a new create. Northwind, the order, and the message ids are fictional. No request leaves this page.
