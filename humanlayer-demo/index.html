      Dex Horthy’s post on 23 Oct 2026 says “its time” and links an X article titled “Open Sourcing HumanLayer”. The same text is on the HumanLayer blog. It says HumanLayer core is open source at github.com/humanlayer/humanlayer, Apache 2.0, and that a build you run yourself sends no telemetry unless keys or DSNs are set. The article signs off Dex and Kyle.
      
    
      What the post says is inside: the desktop app (Electron, plus a Tauri build) and the web app; the daemon that runs Claude Code and Codex sessions, shipped in the humanlayer CLI; the cloud API and the Electric proxy that syncs Postgres; the build sources for the humanlayer-pi and humanlayer-opencode plugins; the RPI skills and the Linear CLI; and the data model of orgs, teams, projects, tasks, sessions, plans and comments, diffs, PRs, and the GitHub, Linear, Jira, and Slack integrations. The repository README adds OpenCode and Pi to the agents the daemon runs, and names the same apps. It says a build from source sends nothing unless Sentry, PostHog, and the WorkOS client ID are set in the environment. The post also says a Docker Compose file can bring the stack up, that some processes still refuse to start without third-party keys such as WorkOS, Slack, and Linear, and that the prompt to hand a coding agent is “walk me through getting the devstack up and running”.
      
    
      humanlayer.dev describes the product as a place where a team steers coding-agent sessions. A task groups sessions, artifacts, and worktrees. The six phases named there are Questions, Research, Design, Structure, and Plan, then Implement. The workflows named there include RPI Guided (“research-plan-implement”), RPI Outline (“Skip planning, implement from outline”), PRD-Oriented, Oneshot (“Implement the ticket or task directly”), and Freeform. This page runs only RPI Guided and Oneshot. Comments on a design document are described as the way people and agents catch a mistake before implementation, and the homepage draws a refresh function gaining a mutex.run around fetch. The two function bodies here follow that drawing. The task name, the file path, and the comment text are this page’s. The FAQ on the marketing site still says the product is not open source yet. This page follows the 23 Oct 2026 post and the repository README, which say the core repo is Apache 2.0.
      
    
      The page does not simulate RPI Outline, PRD-Oriented, or Freeform. It does not show orgs, teams, or projects. It does not pause a tool call for approve, deny, or an edited input: the current post and README describe tasks, sessions, plans, comments, and diffs, and the older daemon approval files are not on the repository’s main branch. Worktree path, daemon socket, and model choice are absent on purpose. The post.
